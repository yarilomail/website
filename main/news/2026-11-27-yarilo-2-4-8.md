# YariloMail 2.4.8: MAILCRYPT and a new folder index

*27 November 2026*

YariloMail 2.4.8 is a release of the 2.4 stable line. It adds MAILCRYPT, the encryption of mail at rest, a folder index that a delivery no longer reads, and the `yarilo-master` supervisor for FreeBSD. **Read "Before you upgrade" first:** a configuration key that nothing reads now stops the load.

## MAILCRYPT: mail encrypted at rest

- **New mail is written in age.** Message bodies are encrypted on disk with [age](https://age-encryption.org) keys. Global keys work in all three storage drivers: mdbox, sdbox and maildir.
- **The `crypt` commands of `yarctl`:** `status`, `keys`, `keygen` and `reencrypt`, which has a dry run. Stored mail is re-encrypted online, to age and back to plain: sdbox, maildir under the folder's uidlist lock, and mdbox one storage file at a time. `--all`, `--jobs` and `--rate` set how much runs at once, and the public namespace is covered.
- **Reading stays cheap.** Unwrapped file keys are cached, and a message is opened once per FETCH response.

[Mail encryption at rest](https://doc.yarilomail.org/latest/storage/mail_encryption.html) describes the keys, how to turn it on and how to rotate a key.

## Folder index and threads

- **A delivery reads no folder.** The folder index holds its records in chunks as their on-disk bytes and shares them between views, so a delivery reads no record chunk.
- **The mdbox map stays on disk,** so a delivery reads none of it.
- **Threads.** The thread store is a sorted base with a log as its tail, and the merge runs outside the lock: a save queues for the thread lock and does not wait for the merge it triggers. A conversation has a size limit.
- **Locks.** Joining a lock queue and trying the lock are a single script, and the lock service exports its CPU time and its Redis time.

## FreeBSD

`yarilo-master` supervises the components and runs a log process of its own. A component gets `GOMAXPROCS=2` unless `master_environment` says otherwise. See [Running on FreeBSD](https://doc.yarilomail.org/latest/installation/single_host.html#running-on-freebsd).

## Configuration, Sieve and tools

- **`yarctl config`** prints the effective configuration, and `yarctl config check` checks a configuration without starting anything.
- **Sieve.** `sieve_send_rate_limit` caps the sends of a mailbox per hour. Redirect loops are detected, duplicates are suppressed, and trace headers are added.
- **mdbox purge** takes `--all` and `--user-file`, and a move to alternate storage now purges too.
- **LMTP.** The backend leg of a delivery is timed by phase.

## Fixed

- **maildir.** An expunged UID never comes back. A message stored with bare LF is served with CRLF, as long as its RFC822.SIZE says. A new keyword letter is given only under the folder's list lock.
- **Shared and virtual namespaces.** LMTP opens a shared namespace as a session does, a virtual mailbox draws from the shared namespaces its patterns reach, and the lock keys and events of a shared store name the store, not the user who opened it.
- **Index.** The GUID store journals its writes and answers from a lookup on disk.
- **Full-text search.** The merged index is sealed before the shards it replaces are removed.
- **Auth.** A userdb chain lists the users of every entry that can list them.

## Before you upgrade

- **An unknown configuration key stops the load.** Before 2.4.8 a key that nothing reads was ignored. Run `yarctl config check` against your configuration before you roll out. `storage.index` is retired: it only warns at start.
- **`ssl_min_protocol` accepts only `TLSv1.2` or `TLSv1.3`.**
- **Config schema 31 → 34:** upgrade the chart and the image together. Pull the new image onto the backend nodes before `helm upgrade`, and keep room for one more backend pod, as for 2.4.7.
- **MAILCRYPT key mounts.** The chart mounts the keys and sets a `sizeLimit` on `/tmp`.

Read the [release notes](https://github.com/yarilomail/yarilo/releases/tag/v2.4.8) before you run `helm upgrade`: they list every change that affects an existing configuration.
